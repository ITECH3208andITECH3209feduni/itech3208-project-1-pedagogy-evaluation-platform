Before you start

Presenter setup

  1. Two windows side by side: this document on the left, the live site on the right. Links here open in one reused tab called pep-live.
  2. Private window for the anonymous part (no one signed in).
  3. Demo account signed in in a normal window — with at least two 2026 attempts (run demo-sprint4-seed.sql if needed).
  4. Admin tab signed in at admin.html ↗.
  5. Expiry screen, prepared: 11+ minutes before your slot, open questionnaire.html ↗ in a separate private window, press Start 10-minute session, answer one question and leave it. Reload it during the demo to show the expired screen without waiting.
  6. Wake the database: load the home page once shortly before presenting.
  7. Keys: ↓/J next feature, ↑/K previous, Space mark as shown.

02

Requirement 6

Anonymous until completion

Client askedThe evaluation should remain anonymous while the session is in progress. Only after the session is completed should the system store the evaluation data.

Show it

  1. In the private window, open Home ↗ → Or continue anonymously.
  2. Optional proof: open DevTools → Network, filter supabase.
  3. Answer questions (keys 1–5 then Enter are fastest) → Review answers.
  4. Show the Network tab is empty → press Submit assessment → one submit_assessment request appears.
They should seeNo requests while answering and reviewing; exactly one database call on submit; "Your results are saved anonymously."
Say“Nothing leaves the browser while someone is answering. The whole evaluation is stored in one transaction only when they submit.”
  • Anonymous while the session is in progress
  • Store data only after the session is completed
03

Requirement 5

Ten-minute session and expiry

Client askedEach evaluation/session should have a 10-minute session time. The system needs to manage what happens when that session expires.

Show it

  1. Point at the timer in the progress bar of any running assessment.
  2. Explain the warnings: amber at 2 minutes, red at 1 minute, announced to screen readers.
  3. Switch to the prepared expiry window and reload it.
  4. Show the expired screen → Start a new session.
They should seeA visible countdown; after 10 minutes “Your 10 minutes ran out”, answers cleared, nothing stored.
Say“Refreshing doesn’t reset the clock. When it expires nothing is saved, and the database also rejects late submissions — so it can’t be bypassed from the browser.”
  • Each evaluation has a 10-minute session
  • Manage what happens when a session expires

Requirement 3

Current and previous attempts

Client askedWhen there are two values/attempts, the system should handle the previous and current result properly.

Show it

  1. In the signed-in window, open Assessment ↗. Note the message about existing 2026 attempts.
  2. Answer all 20 quickly (1–5, Enter) → Review → Submit.
  3. On the completion screen show “Keep your previous attempt?”
  4. Choose Keep both (so the dashboard still has a comparison).
They should seeThe new attempt is the active result; the previous attempt and its score are named; Keep both / Delete previous attempt.
Say“The newest attempt always counts. The previous one is kept for comparison, and the user decides right away whether to keep it.”
  • Handle previous and current attempts properly
05

Requirement 3

Delete or override the previous attempt

Client askedThe user should have the option to delete/override the previous attempt. If the previous attempt is deleted/overridden, only the current attempt should be used as the active result.

Show it

  1. Open Dashboard ↗ → scroll to All attempts.
  2. Show the Active result (no Delete) and the Previous attempt (Delete).
  3. Press Delete on the previous attempt → confirm.
  4. Show the list refreshes: only the current attempt remains active for the year.
They should see“Deleted your previous attempt …”; the Previous attempt row is gone; the active result is unchanged.
Say“The previous attempt can be deleted here or at submission. The active result can never be deleted — the database refuses.”
  • Option to delete/override the previous attempt
  • If deleted, only the current attempt is active

Requirement 4

Historical comparison with charts

Client askedAllow users to compare their current results with previous years/past attempts, including category-wise progress. Show whether scores have improved, decreased, or stayed similar, using graphs/charts.

Show it

  1. On the dashboard, open Compare with and switch between the previous attempt and an earlier year.
  2. Point at the category rows: Improved ▲, Decreased ▼, Stayed similar ● (within ±2 points).
  3. Show the bar chart, then scroll to Year-to-year progress (line chart + table).
They should seePer-category before → after scores with trend labels; comparison bar chart; three-year line chart.
Say“Every category is labelled improved, decreased or stayed similar, and the charts show the same thing visually across years.”
  • Compare with previous years / past attempts, category-wise
  • Show improved, decreased or stayed similar
  • Compare year-to-year
  • Display using graphs/charts
